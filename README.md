# «Тихий Чат» (QuietChat) — фильтр и ассистент домовых чатов в MAX

Проект разработан для трека «Умный город» (Минобрнауки России / MAX).  
Сервис избавляет жителей от информационного шума в домовых чатах: присылает личные уведомления при упоминании квартиры или автомобиля и собирает структурированные выжимки важных событий дома.

- **Чат-бот в MAX**: [@se14396800_bot](https://web.max.ru/355531174)
- **Mini App в MAX**: [https://158-160-226-198.sslip.io](https://158-160-226-198.sslip.io) (Демо-режим: `https://158-160-226-198.sslip.io/?demo=1`)
- **Git-репозиторий**: `https://github.com/Rostyangrib/hakaton-max.git` (ветка `dev-chat-max`)

---

### 1. Назначение решения
В домовых чатах на сотни квартир важные сообщения (аварии стояков, отключения воды, уборка снега, эвакуация машин) тонут в потоке бытовых споров, поздравлений и спама. Большинство жителей выключают звук уведомлений и пропускают критические ситуации.

«Тихий Чат» работает в связке бота и встроенного Mini App без спама в общий чат:
1. **Персональные алерты**: бот находит в общем потоке сообщения, касающиеся конкретной квартиры, подъезда или машины жильца, и моментально присылает их в личные сообщения.
2. **Структурированные сводки**: по запросу формирует выжимку событий дома за день, неделю или месяц по трем разделам (ЖКХ и аварии, двор и парковка, соседские дела) с подсчетом отфильтрованного шума и сэкономленного времени.

### 2. Основной пользовательский сценарий
1. **Подключение**: житель находит бота `@se14396800_bot` в MAX, отправляет команду `/start` и получает меню с кнопкой «Открыть профиль».
2. **Настройка в Mini App**: по клику внутри MAX открывается веб-приложение на `@maxhub/max-ui`. Приложение проверяет криптографическую подпись `initData` и сверяет участие пользователя в чатах домов. Житель выбирает свой дом, указывает квартиру, подъезд, этаж и данные автомобилей (номер, цвет/марка), после чего сохраняет профиль.
3. **Мониторинг без спама**: бот состоит в домовом чате с правами администратора на чтение сообщений, слушает входящий поток через Webhook и никогда не пишет в общую группу.
4. **Мгновенный персональный алерт**: когда в чате появляется сообщение (*«Кв 54, перекройте стояк, заливаете!»* или *«Белая камри А123ВС77, освободите проезд мусоровозу»*), детектор сопоставляет данные с профилем и немедленно доставляет уведомление в личные сообщения жильца с указанием автора и дома.
5. **Получение сводки**: в диалоге с ботом житель нажимает «📅 Сегодня» или «📆 7 дней». Бот опрашивает YandexGPT (со строгой схемой ответа и автоматическим локальным fallback-режимом при недоступности внешнего сервиса) и за 2–3 секунды присылает категоризированный дайджест. Если житель состоит в нескольких домах, бот предлагает выбрать нужный дом инлайн-кнопками.

### 3. Состав и архитектура решения
Монорепозиторий pnpm Workspace на TypeScript / Node.js 22:
- `apps/api`: HTTP-сервер на Fastify 5. Принимает Webhook от MAX Bot API (`POST /webhooks/max`), валидирует HMAC-подпись `initData` Mini App (`POST /api/auth/max`), управляет сессиями и профилями жильцов (`/api/profile`), выполняет JIT-проверку членства в чатах.
- `apps/worker`: фоновый процесс обработки очереди событий из PostgreSQL. Выполняет детекцию триггеров (`detectors.ts`), отправку личных алертов (`private-alert.ts`), генерацию AI-сводок через YandexGPT (`summary-service.ts`) с кэшированием и антифлудом.
- `apps/web`: мобильное веб-приложение (MAX Mini App) на React 19, `@maxhub/max-ui` и Vite.
- `packages/database`: PostgreSQL 16, схема и миграции через Drizzle ORM.
- `packages/shared`: общие Zod-схемы валидации, DTO и контракты API.
- `packages/config`: строго типизированная конфигурация переменных окружения на Zod.
- `deploy`: образы Docker, конфигурация Caddy 2 (TLS Let's Encrypt), скрипты бэкапов в S3 Object Storage и очистки данных.

### 4. Команда запуска всех локальных компонентов через Docker
```bash
docker compose up --build
```

### 5. Необходимые параметры окружения
- Docker Engine 24+ и Docker Compose v2;
- Node.js >= 22 (для локального запуска без Docker);
- pnpm 12.5.1 (`corepack enable pnpm`);
- Свободные порты: 3000 (API), 5173 (Mini App Web), 5432 (PostgreSQL).

### 7. Используемые порты
- `3000`: Fastify API (вебхуки, проверка готовности `/health/ready`, REST API профиля);
- `5173`: Vite Development Server (локальная раздача интерфейса Mini App);
- `5432`: PostgreSQL 16 (доступен только внутри изолированной Docker-сети);
- `80` / `443`: Caddy Reverse Proxy с автоматическим TLS-сертификатом на сервере.

### 8. Зависимости

### 9. Внешние сервисы и интеграции
1. **Платформа MAX (Bot API и MAX Bridge)**:
   - Входящие события поступают через Webhook (`POST /webhooks/max`). Исходящие вызовы (`sendMessageToUser`, `getChatMembers`, `editMessage`) выполняются строго по контрактам Bot API.
   - Эмулятор MAX в Docker отсутствует. Для локальной проверки интерфейса Mini App поддержан автономный демо-режим: `http://localhost:5173/?demo=1`.
2. **Yandex Cloud (YandexGPT Foundation Models)**:
   - Используется для суммаризации сообщений методом `foundationModels/v1/completion`.
   - Если ключ не задан или сервис недоступен, воркер переключается на встроенный детерминированный классификатор ключевых слов (`mode: fallback`). Сводки формируются в 100% случаев.
3. **Yandex Object Storage (Production)**:
   - Хранение резервных копий PostgreSQL с автоматическим удалением через 7 дней.

### 10. Описание работы с данными
- **Таблицы базы данных**:
  - `users`: учетные записи пользователей MAX (`max_user_id`, имя, даты старта/остановки бота);
  - `homes`: подключенные домовые чаты (`max_chat_id`, название, часовой пояс, статус активности);
  - `resident_profiles`: привязка жильца к дому (`apartment`, `entrance`, `floor`, `vehicles`, флаг алертов, статус членства);
  - `messages`: журнал сообщений чата (`max_message_id`, отправитель, текст, хеш, дата отправки, дата удаления `deleted_at`);
  - `alert_deliveries`: журнал доставленных личных алертов и блокировки антифлуда;
  - `summary_jobs`: кэш сгенерированных сводок с привязкой к периоду и количеству сообщений;
  - `webhook_events`: очередь входящих вебхуков с защитой от дублей по SHA-256 и статусами обработки (`pending`, `processing`, `done`, `failed`).
- **Сроки хранения**: сообщения хранятся 30 дней, сырые вебхуки — 7 дней. Кэш сводок инвалидируется при поступлении новых сообщений в чат.

### 11. Порядок работы с тестовыми данными
В соответствии с п. 10 регламента хакатона, в MVP используются смоделированные данные:

- Профиль жильца для проверки: квартира `54`, подъезд `3`, этаж `8`, автомобиль `А123ВС77` (Белая Toyota Camry);
- Автономный режим Mini App для проверки верстки: `https://158-160-226-198.sslip.io/?demo=1`.

### 12. Пошаговый сценарий проверки
1. **Проверка готовности сервисов**:

   Ожидаемый ответ: `HTTP 200 OK` с телом `{"status":"ok","service":"api",...}`.

3. **Проверка сценария бота в MAX**:
   - Открыть диалог с ботом: [@se14396800_bot](https://web.max.ru/355531174).
   - Отправить `/start` — убедиться в получении меню с кнопками.
   - Нажать «📅 Сегодня» — бот обновляет сообщение статусом «Готовлю сводку…» и присылает выжимку по трем категориям с указанием сэкономленного времени.
4. **Проверка адресного алерта**:
   - В домовой чат отправить сообщение: *«Чья машина А123ВС77 во дворе? Срочно уберите!»* или *«Кв 54, перекройте стояк!»*.
   - Убедиться, что в личный диалог с ботом приходит персональное уведомление с цитатой, автором и названием чата дома.

### 14. Известные ограничения
1. **Обработка текста**: в рамках MVP обрабатываются только текстовые сообщения чата (распознавание фото объявлений и аудиосообщений запланировано на этапе масштабирования).
2. **Права бота в группе MAX**: для получения входящих сообщений от участников чата бот должен быть назначен администратором группы с правом «Чтение всех сообщений» (`read_all_messages`).
3. **Антифлуд**: настраивается параметром `ALERT_ANTIFLOOD_MINUTES` (по умолчанию отключен `0` для удобства тестирования жюри).
