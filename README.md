# QuietChat («Тихий Чат») — Умный фильтр и персональный ассистент домового чата в MAX

Решение для трека «Умный город» хакатона Минобрнауки России и платформы MAX.  
Превращает шумный поток сотен сообщений многоквартирного дома в персональные мгновенные алерты ЖКХ и структурированные AI-сводки.

- **Чат-бот в MAX**: [@se14396800_bot](https://web.max.ru/355531174)
- **Mini App в MAX**: [https://158-160-226-198.sslip.io](https://158-160-226-198.sslip.io) (Демо-режим: `https://158-160-226-198.sslip.io/?demo=1`)
- **Git-репозиторий**: `https://github.com/Rostyangrib/hakaton-max.git` (ветка `dev-chat-max`)

---

### 1. Назначение решения
QuietChat решает проблему информационного шума и пропуска критически важных жилищно-коммунальных событий в общих домовых чатах многоквартирных домов (МКД). В типичном чате на 200–500 жильцов важные объявления (аварии стояка, отключение горячей воды, опрессовка, замена лифта, уборка снега с риском эвакуации авто) тонут среди сотен бытовых сообщений, споров и спама. 

QuietChat выступает в роли «тихого наблюдателя» в чате дома:
1. Выделяет сообщения, затрагивающие конкретную квартиру, подъезд, этаж или автомобиль жильца, и немедленно присылает персональное push-уведомление в личный диалог с ботом.
2. По запросу генерирует структурированную выжимку событий дома за выбранный период (сегодня, 7 дней, 30 дней) с категоризацией по ЖКХ, двору и соседскому сообществу, экономя жильцу до 40 минут времени в день.

### 2. Основной пользовательский сценарий
1. **Подключение и настройка**: Житель находит бота `@se14396800_bot` в MAX, нажимает `/start` и получает приветственное сообщение с кнопкой «Открыть профиль».
2. **Авторизация и сохранение данных в Mini App**: По клику открывается веб-приложение на `@maxhub/max-ui`. Приложение прозрачно верифицирует криптографический `initData` пользователя MAX. Житель вводит номер квартиры, подъезда, этажа и данные автомобиля (госномер, марка/цвет), после чего нажимает «Сохранить».
3. **Автоматический мониторинг**: Бот состоит в домовом чате с выключенным звуком и слушает входящие сообщения через Webhook. Бот никогда не спамит в общую группу.
4. **Мгновенный персональный алерт**: Сосед или управляющая компания пишет в домовой чат: *«Квартира 54, перекройте стояк, вы заливаете соседей!»* или *«Белая камри А123ВС77, переставьте машину, чистят снег»*. Детектор триггеров сопоставляет сообщение с профилем, и житель мгновенно получает личное сообщение от бота с цитатой и автором.
5. **Получение структурированной AI-сводки**: В любой момент житель может нажать в диалоге с ботом кнопку «📅 Сегодня» или «📆 7 дней». Бот за 2-3 секунды формирует сводку на базе YandexGPT (с гарантированным фолбэком на детерминированные правила) с разделами: 🔴 ЖКХ и аварии, 🟡 Двор и транспорт, 🟢 Соседские дела, а также показывает счетчик отфильтрованного шума и сэкономленного времени.

### 3. Состав и архитектура решения
Монорепозиторий pnpm Workspace на TypeScript / Node.js 22:
- `apps/api`: Бэкенд Fastify 5. Принимает Webhook от MAX Bot API (`POST /webhooks/max`), валидирует HMAC-подпись `initData` Mini App (`POST /api/auth/max`), выдает сессионные токены (`POST /api/auth/token`) и управляет профилем жильца (`/api/profile`). Проверяет членство в домовом чате через Bot API.
- `apps/worker`: Фоновый демон обработки очереди сообщений и интерактивных callback. Содержит движок детекции триггеров (`detectors.ts`), сервис генерации сводок (`summary-service.ts`) с клиентом YandexGPT (`yandex-gpt.ts`), кэшированием в PostgreSQL и антифлуд-блокировками.
- `apps/web`: Mini App на React 19, `@maxhub/max-ui` и Vite. Полностью адаптивный интерфейс (320px–desktop) с соблюдением цветовой схемы и гайдлайнов MAX.
- `packages/database`: Слой доступа к данным (PostgreSQL 16, Drizzle ORM, миграции схемы).
- `packages/shared`: Общие типы, схемы валидации Zod (контракты MAX, нормализация госномеров).
- `packages/config`: Типобезопасная загрузка конфигурации окружения.
- `deploy`: Caddy 2 (автоматический TLS Let's Encrypt), systemd-сервисы, скрипты ротации и резервного копирования в S3 Yandex Object Storage.

### 4. Команда запуска всех локальных компонентов через Docker
```bash
docker compose up --build
```

### 5. Необходимые параметры окружения
- Docker Engine 24+ и Docker Compose v2;
- Node.js >= 22 (при локальной разработке без Docker);
- pnpm 12.5.1 (`corepack enable pnpm`);
- Свободные порты: 3000 (API), 5173 (Mini App Web), 5432 (PostgreSQL).

### 7. Используемые порты
- `3000`: Fastify API (бэкенд, healthcheck, прием вебхуков и API профиля);

### 9. Внешние сервисы и интеграции
1. **Платформа MAX (Bot API & WebApp Bridge)**:
   - Взаимодействие через вебхук `POST /webhooks/max` и вызовы `sendMessageToUser`, `getChatMembers`, `editMessage`.
   - Внутри Docker запустить эмулятор MAX невозможно. Проверка сценария выполняется либо через подключение реального тестового бота, либо через встроенный визуальный тестовый режим Mini App `http://localhost:5173/?demo=1`.
2. **Yandex Cloud (YandexGPT Foundation Models)**:
   - Используется для суммаризации сообщений по модели `foundationModels/v1/completion`.
   - Если API-ключ Yandex Cloud не указан или сервис недоступен, воркер автоматически переключается на встроенный детерминированный алгоритм категоризации (`mode: fallback`), гарантируя 100% доступность сводок.
3. **Yandex Object Storage (Production)**:
   - Используется на боевом сервере для хранения зашифрованных ежедневных бэкапов PostgreSQL со сроком хранения 7 дней.

### 10. Описание работы с данными
- **Таблицы БД**:
  * `users`: пользователи MAX (id, first_name, last_name, username, created_at);
  * `resident_profiles`: профиль жильца (квартира, подъезд, этаж, номер авто, марка/цвет, флаг включения алертов);
  * `chat_messages`: журнал сообщений домового чата (id, sender, text, sent_at, deleted_at);
  * `alert_deliveries`: история доставленных алертов для соблюдения антифлуда;
  * `summary_jobs`: кэш и журнал сформированных сводок (period, result JSON, message_count).
- **Политика хранения**: сообщения хранятся 30 дней, сырые вебхуки — 7 дней, кэш сводок инвалидируется при поступлении новых сообщений в чат.

### 11. Порядок работы с тестовыми данными
В соответствии с п. 10 ограничений регламента, в MVP используется смоделированный домовой чат:
- Тестовый чат дома: `MAX_HOME_CHAT_ID=-79181109403700`.
- Эталонный тестовый жилец: квартира `54`, подъезд `3`, этаж `8`, автомобиль `A123BC77` (Белая Toyota Camry).
- Для локальной проверки верстки Mini App без привязки к сессии MAX доступен URL с флагом `?demo=1`.

### 12. Пошаговый сценарий проверки
1. **Проверка работоспособности сервисов**:
   Выполнить запрос готовности: `curl https://158-160-226-198.sslip.io/health/ready`  
   Ожидаемый ответ: `HTTP 200 OK {"status":"ok","service":"api"}`.
2. **Проверка Mini App**:
   Открыть в браузере или клиенте MAX: `https://158-160-226-198.sslip.io/?demo=1`.  
   Убедиться в корректности отображения SVG-домов, бейджа пользователя, полей квартиры/авто и адаптивности без горизонтальной прокрутки.
3. **Проверка бота в MAX**:
   - Перейти в диалог с ботом: `https://web.max.ru/355531174` (`@se14396800_bot`).
   - Отправить команду `/start` — бот присылает приветствие и клавиатуру с кнопками «Открыть профиль», «📅 Сегодня», «📆 7 дней».
   - Нажать «📅 Сегодня» — бот обновляет сообщение статусом «Генерирую сводку...» и присылает структурированную выжимку по трем блокам.
4. **Проверка адресного алерта**:
   - При отправке в домовой чат фразы: *«Чья машина А123ВС77 во дворе? Срочно уберите!»* бот доставляет в личный диалог жильца уведомление:  
     `🔔 В домовом чате упомянули: автомобиль A123BC77.`  
     `«Чья машина А123ВС77 во дворе? Срочно уберите!»`  
     `Автор: Иван Сосед`

### 14. Известные ограничения
1. **Текстовый фокус**: в MVP анализируются только текстовые сообщения (распознавание сканов объявлений и аудиосообщений запланировано на этапе масштабирования).
2. **Один домовой чат в MVP**: конфигурация зафиксирована на пилотный дом `MAX_HOME_CHAT_ID`.
3. **Антифлуд-таймаут**: повторные сообщения с одинаковым триггером от одного автора игнорируются в течение 15 минут для предотвращения спама.

docker compose down -v && docker compose up --build
