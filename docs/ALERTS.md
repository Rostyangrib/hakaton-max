# Сообщения и персональные алерты

## Обработка событий

- `message_created` из `MAX_HOME_CHAT_ID` сохраняется по `body.mid` с upsert.
- `message_edited` обновляет текст, нормализованный текст, hash и `edited_at`.
- `message_removed` устанавливает `deleted_at`; запись сохраняется для аудита и исключается из будущих сводок.
- Личные сообщения и события других чатов в хранилище домового чата не попадают.
- Автор сообщения исключается из списка получателей.

## Детерминированные детекторы

- квартира — упоминание числа рядом с `кв.`, `квартира` и распространёнными формами слова;
- подъезд — число рядом со словом `подъезд` или `под.`;
- госномер — российский формат с допустимыми кириллическими или визуально эквивалентными латинскими буквами;
- описание автомобиля — одновременно должны совпасть цвет и хотя бы одно слово марки/модели из профиля.

Детектор не считает время, телефон или обычное число номером квартиры без явного маркера. Для описания автомобиля одного цвета недостаточно.

## Доставка и антифлуд

1. Для каждого подходящего профиля pipeline формирует уникальные триггеры.
2. PostgreSQL advisory lock сериализует проверки одинакового `профиль + автор + тип + значение`.
3. Если успешная или выполняющаяся доставка с тем же ключом создана менее 15 минут назад, новый алерт подавляется.
4. На одного получателя отправляется не более одного сообщения для одного исходного сообщения.
5. Внешний интерфейс доставки содержит только `sendMessageToUser`; метода отправки в чат в нём нет.
6. Неудачная отправка получает статус `failed` и повторяется при retry исходного webhook.

Интервал настраивается через `ALERT_ANTIFLOOD_MINUTES`.

## Формат личного сообщения

Алерт содержит:

- сработавшее поле профиля;
- фрагмент исходного сообщения не длиннее 240 символов;
- имя автора сообщения.

Публичная ссылка на сообщение не добавляется, поскольку она находится вне границ MVP.
