# AI-сводки

## Пользовательский сценарий

В личном диалоге с ботом доступны три callback-кнопки: `Сегодня`, `7 дней` и `30 дней`. Сводка отправляется только пользователю, который нажал кнопку. Callback из группового чата не обрабатывается, а метод отправки в общий чат не используется.

Запрашивать историю может только пользователь с подтверждённым профилем жильца в настроенном `MAX_HOME_CHAT_ID`.

## Периоды

- `today` — от 00:00 текущего дня в часовом поясе дома до момента запроса;
- `week` — скользящие последние 7 суток;
- `month` — скользящие последние 30 суток.

Из PostgreSQL выбираются только текстовые сообщения дома с `deleted_at IS NULL`.

## Подготовка и map-reduce

Шаблонные приветствия удаляются. Если в исходной выборке больше 150 сообщений, соседние короткие сообщения одного автора объединяются, при этом сохраняются ID всех источников. Затем данные разбиваются на блоки до 75 записей.

Каждый блок проходит map-запрос к YandexGPT. При нескольких блоках выполняется reduce-запрос: промежуточные результаты объединяются, дубликаты удаляются. Тексты чата явно помечены в системном промпте как недоверенные данные, чтобы инструкции из сообщений не меняли задачу модели.

## Контракт модели

YandexGPT вызывается синхронным методом `foundationModels/v1/completion` с `jsonSchema`. По умолчанию используется URI `gpt://<folder-id>/yandexgpt/latest`; его можно заменить через `YANDEXGPT_MODEL_URI`.

Ответ содержит только три массива:

- `housing` — ЖКХ и аварии;
- `yard` — двор и транспорт;
- `community` — соседские дела и находки.

У каждого пункта есть `text` и `sourceMessageIds`. Ответ повторно проверяется Zod-схемой. Любая ссылка на неизвестный ID, невалидный JSON, обрезанный ответ или ошибка API переводит запрос в резервный режим. Благодаря сохранённым ID каждый факт можно сопоставить с исходными сообщениями, хотя ID не показываются пользователю.

Пустая категория выводится как `Без происшествий`. Финальное MAX-сообщение ограничено 4000 символами: показываются первые пять пунктов каждой категории, каждый не длиннее 200 символов.

## Кэш и резервный режим

Готовый результат хранится в `summary_jobs`. Повторный запрос того же пользователя, дома и периода в течение `SUMMARY_CACHE_TTL_SECONDS` (по умолчанию 600 секунд) возвращается из PostgreSQL без повторного вызова модели.

Если ключи не настроены или YandexGPT недоступен, применяется детерминированный словарный классификатор. Такой результат имеет `mode=fallback`, сохраняется в кэш и явно помечается пользователю как резервный.

## Переменные окружения

- `YANDEX_CLOUD_FOLDER_ID` — ID каталога Yandex Cloud;
- `YANDEX_CLOUD_API_KEY` — API-ключ сервисного аккаунта, только в локальном `.env`/хранилище секретов;
- `YANDEXGPT_MODEL_URI` — необязательный URI модели;
- `YANDEXGPT_API_URL` — endpoint API;
- `YANDEXGPT_TIMEOUT_MS` — таймаут одного запроса, по умолчанию 12 секунд; две фазы map-reduce укладываются примерно в 24 секунды;
- `SUMMARY_CACHE_TTL_SECONDS` — TTL кэша, по умолчанию 10 минут.

Секреты не должны попадать в Git или логи. Для production сервисному аккаунту нужна роль `ai.languageModels.user` и подходящая область действия API-ключа.

## Ограничения текущего этапа

Реальный вызов YandexGPT и end-to-end сценарий в MAX не выполнялись: рабочий `.env`, публичный HTTPS webhook и `MAX_HOME_CHAT_ID` ещё не настроены. Интеграция проверяется unit-тестами с подменённым HTTP-ответом.

Официальная документация: [генерация текста](https://aistudio.yandex.ru/ru/docs/ai-studio/text-generation/api-ref/TextGeneration/completion), [API-ключи](https://yandex.cloud/ru/docs/iam/concepts/authorization/api-key), [отправка сообщений MAX](https://dev.max.ru/docs-api/methods/POST/messages).
